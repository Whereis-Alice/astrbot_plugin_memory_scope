# 内存涨了，当时发生了什么？

## 两种入口

- **总览 → 趋势图**：点击一个位置，查看前后约 30 秒的内存和活动。电脑上也可以拖动放大，再点「分析当前区间」。键盘左右键选点，Enter 查看，Escape 关闭。
- **最近活动**：自动保存，不必每次手动运行。可按时间、类型、插件筛选，翻页查看更早记录，也可以选择过去的启动批次。「查看同期内存」会打开对应区间。

手机可轻点趋势点；滑动页面不会当成点击。分析最多覆盖 24 小时。页面会显示实际采样时间，缺测显示 `—`，不是零。

## 能看到什么

| 记录 | 含义 |
| --- | --- |
| 插件处理 | 已接入的异步处理函数执行窗口，包括等待和生成器暂停时间，不是纯 CPU 耗时 |
| 模型请求 | AstrBot 模型请求到返回的窗口；失败或中止可能没有结束回调 |
| 工具调用 | 工具名称和调用窗口；能识别来源时显示插件，否则显示 AstrBot/MCP |
| 生命周期 | 观察插件启用后收到的插件加载、卸载通知，不能补回更早的通知 |
| 内存诊断 | 手动或自动审计、引用图/对象扫描以及手动 GC |
| 进程变化 | 后端采样发现进程出现、消失；只保留名称和 PID，不记录命令参数 |
| 分配追踪 | 管理员手动运行的 Python 分配位置差异 |

增长分析分别显示服务总量、匿名驻留、文件缓存、内核记账、Swap，以及进程 RSS 变化。服务总量已经包含子进程；这些口径不能全部相加。进程按 PID 和启动标识匹配，PID 被复用时不会算成同一个进程。

**活动重叠只是线索，不是判定责任。** 例如同一时间有图片处理和模型回复，不能把全部增量算给图片插件。共享库、缓存、原生库分配、未接入的定时器/后台任务也可能贡献增长。无法恢复安装本功能之前的操作。

进程明细和总量采样频率不同，进程值可能较端点时间稍旧。采样间隙内的短命进程、瞬时峰值可能遗漏。「未收到结束」表示缺少结束证据，不能直接认定任务还在运行。

## 默认配置与保存

- `activity_recording_enabled = true`：连接后端后记录功能名称与时间。不保存消息正文、用户/群标识、提示词、参数、结果和异常内容。
- `activity_max_per_minute = 300`：每分钟最多开启 300 条插件侧记录；可设 30～3000。超过会跳过并显示丢弃数。不是消息限流，不影响其他插件执行。
- 内存队列最多 512 条，未结束窗口最多 256 个，超过 30 分钟的窗口标记失去结束证据。后端暂时不可用会保留有限队列，不无限堆积。
- 有活动时每 5 秒批量同步，空闲时约 30 秒心跳；页面还受自动刷新间隔影响，因此不是毫秒级实时。
- 记录存在独立后端 SQLite 中，重启保留。活动独立限制为最近 20000 条，并受后端保存天数和数据库容量限制；繁忙时不足 7 天是正常的。后端数据库已满也可能丢弃记录。
- 关闭插件记录后，后端仍会记录采样发现的进程变化。关闭不会清空历史。

两端都需要更新。只更新插件、后端仍旧时，页面会明确报错，不把接口缺失伪装成「没有活动」。

## 会不会影响速度

普通记录只取时间和功能名称，每次调用不扫描内存、不读 RSS、不写磁盘、不等待网络；上报和存储放在批处理。仍有少量函数包装、序列化和后台 I/O 开销，繁忙时有速率上限。插桩约每分钟重新发现一次，刚安装的处理函数可能延迟接入。

本地 Windows / Python 3.14 微基准（15 轮，每轮 1000 次空协程）：裸调用中位约 0.12 微秒，附加完整起止记录约 7.89 微秒；队列保持 512 条上限。这只衡量直接记录路径，**不含上报、数据库、SDK 插桩或真实业务**，不能拿它当服务器总开销保证。

趋势分析在独立后端执行，流式读取区间，只留两端的完整进程明细，避免一次加载全天的进程树。查询仍会使用后端 CPU 和磁盘；不要连续发起全天分析。

### 限时分配追踪：需要时才开

仅在 AstrBot 内嵌页手动确认后运行，界面默认 30 秒，API 允许 10～60 秒，可以提前停止。**不在启动时开启，不因查看页面而开启，也不会重启机器人。**

它会增加 CPU 和内存消耗，可能让回复变慢。繁忙或内存紧张时不建议使用。每秒检查追踪器自身记账，超过 16 MiB 提前退出；这是尽力保护，**不是整个进程的硬内存上限**，快照和差异计算还会额外占内存。若事件循环阻塞，停止也可能延后。

结果只列开启之后 Python 分配位置的净增长前 20 项，不含源码正文；不是函数累计分配量，也不是全部原生内存。如果其他工具已经开启 tracemalloc，本功能拒绝接管。结束、取消和插件正常卸载时会停止自己开启的追踪器。

想进一步验证责任，需要控制消息负载并做重复对照，参见[测量口径](measurement.md)。
