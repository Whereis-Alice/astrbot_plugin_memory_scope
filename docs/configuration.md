# 日常查看 WebUI，配置怎么选

日常建议用服务器采集器持续记录，随时打开 **MemoryScope → 总览**。总览显示当前服务内存与子进程；启动记录保留上次启动时各插件的阶段增量。查看报告不需要重启，启动增量也不是各插件此刻的独占内存。

## 先分清两种使用方式

- **已配置采集器**：服务器有独立的 MemoryScope 服务，插件负责显示结果和同步插件名单。配置了连接信息就按此模式运行；采集器暂时失联时会提示错误，不会偷偷启动重型扫描补数据。
- **仅本地模式**：只装 AstrBot 插件，没有配置服务器采集器。本地采样和自动诊断才使用相应的开关。

配置标题中标有“本地”的选项，不控制服务器采集器。勾选框保存的是你的设置，下面的模式规则会决定它是否实际启用。

## 已配置采集器时的推荐值

| 配置项 | 推荐值与实际效果 |
| --- | --- |
| 连接配置文件 `observer_config_path` | 同机常用 `/etc/memoryscope/observer.json`；观测启动入口可以自动发现，不必填 |
| 手动地址与凭据 `observer_url` / `observer_token` | 使用配置文件或自动发现时，两项都留空 |
| 本地导入统计 `measure_import_cost` | 无需为了性能特意改勾选；此模式下自动停用，不影响早期探针 |
| 自动对象普查 `census_enabled` | 保持关闭；此模式下即使勾选，也不会自动执行 |
| 允许引用图扫描 `deep_scan_enabled` | 保持开启，允许需要时手动查一次 |
| 自动引用图扫描间隔 `deep_scan_interval_samples` | 保持 0，即仅手动；此模式下会强制使用 0 |
| 额外统计对象总数 `include_object_count` | 关闭，仅增加一个统计数字，不提高归属准确性 |
| 插件后台工作间隔 `sample_interval_seconds` | 60 秒；此模式下用于同步名单。服务器常态内存采样仍默认每 5 秒一次 |
| 本地历史保存 `persist_history` | 此模式下自动停用；服务器历史另行保存，仍可查看 |
| 本地告警阈值 | 日常保持 0；此模式下不会周期执行本地告警检查 |

其他选项通常保持默认。只想看大概情况，不需要创建重启对照实验，也不需要把对象扫描全部打开。

## 为什么以前写“导入统计推荐开启”

这句话只适用于仅本地模式：本地钩子能统计在 MemoryScope 之后加载的插件，所以默认开启有帮助，但看不到之前加载的插件。

配置采集器后，本地钩子自动停用；若使用带早期探针的启动入口，启动阶段由它记录。**开关不是互相矛盾的两个建议，而是适用于两种模式。** 单独关闭本地开关不会关掉早期探针；调整早期探针要改服务器启动入口。

## 对象普查能多看见什么

它枚举 Python 跟踪的存活对象，按“对象类型在哪个模块定义”进行分类，再统计对象数量和浅层大小。适合发现某种插件自定义对象是否越来越多。

它不能给出插件完整内存账单：

- 插件创建的普通字典、列表，类型仍是 Python 内置类型，不一定能归到这个插件。
- 另一个插件或框架也可以持有某插件定义的对象；类型来自谁，不代表现在是谁在持有。
- 大量字符串、字节数据不在这种枚举范围内，图片缓冲区、第三方库的底层分配和浏览器子进程也无法完整覆盖。
- 默认每 10 个对象抽查一个，再放大估算；小类别可能漏掉。改成逐个检查只能减少抽样误差，不能补齐上述缺口。

所以它增加的是另一条排查线索，**不是开启后所有插件的内存准确率就会明显提高**，也没有可承诺的准确百分比。想估算哪些对象仍被插件引用，可以手动用引用图扫描补充判断；两种结果都不能直接当作独占 RSS。

## 对象普查可能多花多少资源

下面是机制推算，不是该服务器刚做过的普查实测：

- 在 64 位 Python 中，每 100 万个被跟踪对象，仅临时名单的指针就约 8 MB；300 万约 24 MB，另外还要统计表等空间。默认抽样也必须先建立完整名单，所以不会把这部分降到十分之一。
- 默认十分之一抽样时，可先按几十至数百毫秒的量级理解扫描开销；对象特别多、CPU 忙或有内存换入时可能达到秒级或更久。没有实际扫描，不能仅凭插件数量准确推算。
- 完整扫描耗时不等于机器人完全停止回复的时长。扫描在工作线程中执行，但仍可能争用 Python 执行时间；建立名单和部分对象处理可能导致停顿，后台线程不能保证零影响。
- 默认 4000 毫秒是工作预算，不是严格的最大卡顿：名单创建和当前处理的工作不能立即中断。

在已配置采集器的模式下，勾选自动普查本身不会引入这些开销，因为它被强制关闭。**手动点击“运行普查”才会实际执行一次。** 仅本地模式若开启自动普查，会在后台采样及需要普查的本地报告中反复执行，因此还应留意页面刷新频率。

日常建议保持自动普查关闭；怀疑某类对象不断积累时，手动运行，查看页面标出的耗时、抽样率和是否扫描完整。

## 配置说明更新后如何看到

重新打开插件配置页；如果仍显示旧说明，重载一次 **MemoryScope 插件**后再打开。无需为文案更新重启整个 AstrBot。此次说明更新保留全部配置键、类型和默认值，不会开启扫描或改动用户已保存的配置。
